## §0 文档说明

### 0.1 本文档是什么，不是什么

**是**：一份"如果真要做，它得长什么样"的完整推演——细到能被验收、能被审计、能被估算工期。作者不会去实现它；这份推演的价值在于**先把"哪里会崩"想清楚**，也方便别人拿去接着想。任何一条"体验承诺"都必须落成可验收的规格；落不成的，不写。

**不是**：
- 不是创意提案。创意只保留在 §1，且只保留能约束生产的条目。
- 不是营销文案。"电影级""暴击""最狠的那一个"这类词，一律必须落成可测量指标，落不成的删掉。
- 不是完整实现说明书。它定义**必须要什么、什么算做对了**，不规定每一行代码怎么写。
- 不是"因为开源所以宽松"的文档。开源只影响披露范围，**不降低任何验收标准**（D-10 附带条款）。

### 0.4 参数管理规则

本文档所有具体数字分三类，必须带标记，禁止混用：

| 标记 | 含义 | 谁能改 |
|---|---|---|
| `【锁】` | 设计红线，与体验承诺绑定（如"六维 0~100""不可读档""单周目 20h"） | 仅用户裁决（L3） |
| `【标定】` | 初值为策划估计，必须在 M1 阶段用实验标定后写回 §10.1 | 主策 + 数据，记入 §10.3 |
| `【实测】` | 来自真实测量 | 只允许被新的实测替换 |

**禁止**把 `【标定】` 当作已验证结论对外传播；对外一律表述为"设计目标值"。

### 0.5 变更流程

1. 提变更单：改哪一节、改成什么、为什么、影响面（引用该节的系统清单）。
2. 判等级：
   - **L1 参数**：只动 §10.1 的 `【标定】` → 主策批准，记 §10.3。
   - **L2 结构**：动 schema、判定公式、章节配额 → 主策 + 技术负责人，版本号 +0.1。
   - **L3 承诺**：动 §1.2 三条不可协商、§0.3 裁决、结局顺序、合规红线、开源披露边界 → **必须用户裁决**，版本号 +1。
3. 变更后必须重跑 §9 审计器（脚本 `audit.ps1`），结果附在变更单后。审计不通过不得合入。

## §1 产品定义

### 1.1 一句话

**你从 13 岁活到 41 岁，遇见四个女人。没有人给你攻略，没有人告诉你错过了什么。二十年后，系统把你错过的、看不见的、她那一侧的全部翻出来给你看，然后让她们当面跟你说最后一句话。**

可以重来的是游戏，不可以重来的是人生——所以第二周目起，你可以从任意一章重新活一次，但系统永远不会告诉你上次错在哪。

### 1.2 三条不可协商（NC）

任何设计冲突以此裁决，**不得以"开源"或"AI 能力更强"为由突破**。

| 编号 | 条款 | 可验收的含义 | 违反示例 |
|---|---|---|---|
| **NC-1** | **人生不可逆** | 一周目内：无存档回退、无章节重选、无"刚才那句我重说"、无历史记录可翻看；所有时间戳单向递增。**重生只在通关后解锁**（D-06/D-09） | 出现"重新选择"按钮；允许读取任意节点 |
| **NC-2** | **双线揭示** | 每一个进入结局池的暴击，必须在游戏过程中真实产生过一条 NPC 侧记录，且该记录有 `causeId`（因果）；震撼来自信息差回收，不来自新编剧情 | 结局时现场编造"她其实一直在等你" |
| **NC-3** | **规则管命运，LLM 管表达** | 所有数值变化、状态迁移、分支走向、谁分手、谁暗恋、谁返场、结局族判定，**100% 由确定性规则产生**；LLM 输出只能是自然语言，不得写入任何数值字段 | LLM 自由发挥导致角色"性格突变式原谅" |

**推论**：任何"因为有 AI 所以更自由"的说法都不能突破 NC-3。AI 的自由度全部在**表达层**，命运层必须可复现——这一条同时是 §2.15 重放和 §9.7 回测的技术前提。

### 1.3 一套内核·三种外壳

用户判断"底层完全一样"，本版把这句话落成一条可执行的架构约定：**数据结构同一套，目标函数不同**。

**三个共用原语（必须最先建，建不好则后面全部失效）**

| 原语 | 定义 | 长河里的形态 | 史鉴里的形态 | 不达标的后果 |
|---|---|---|---|---|
| **tick** | 世界在玩家不在场时按规则自主推进 | NPC 离线生活、客观事实推进 | 历史主体按约束与认知演进 | NPC 变木头，结局无素材可回收 |
| **fork-replay** | 从状态快照 + 输入日志确定性重放 | 重生/NG+/二周目 | 反事实分支、历史回测 | 只能靠编剧硬写分支，成本指数上升 |
| **trace** | 因果链 + 知识边界可追溯 | 每条伏笔可追到前置原因 | 每条结论可追到史料与证据等级 | 退化成"流畅但不可证伪的漂亮话" |

**两种验收函数（不可混用）**

| | 长河 | 史鉴 |
|---|---|---|
| 成功判据 | 情绪：玩家被击穿（§1.4） | 可证伪：回测能收敛到已知结局、结论可溯源 |
| 数据源 | 世界库 = 创作事实 | 世界库 = 史料 + 证据等级 |
| 摄像机位 | 第一人称，参与者 | 上帝视角，观察者 |
| 失败模式 | 不好玩 | 不可信 |
| 约束强度 | 事实可改（虚构） | 事实不可改（史实为硬约束） |

**三种产品（同一内核的三个外壳）**

| 产品 | 摄像机位 | 验收函数 | 本版是否实现 | 载体 |
|---|---|---|---|---|
| 长河 · 主线 | 第一人称 | 情绪（长线 20h） | V2 档位 | §8.1 配额 |
| 长河 · 内容包 | 第一人称 | 情绪（2~3h 高浓度） | **V0 档位（先做这个）** | §8.4 |
| 史鉴（暂名） | 上帝视角 | 可证伪 | 仅内部回测实验 | §9.7 |

**对外表述纪律**：可以说"一套内核，三种外壳"；**不得**说"做游戏和历史研究完全一样"——验收函数不同就是两种工程（§1.3 表二），这句话会被专业的人一句话打回。

### 1.4 四个尺度的体验承诺

| 尺度 | 玩家应该感受到什么 | 验收方式 |
|---|---|---|
| **30 秒** | 第一次对话，你觉得她在听你说话，而不是在放录音 | 首测：被试说出"她刚才那句话是针对我说的"比例 ≥ 70%【标定】 |
| **10 分钟** | 你意识到没有选项框、没有好感度、没有人告诉你该说什么，但压力在 | 被试能自主说出 ≥2 个"我该说什么"的瞬间 |
| **20 小时** | 你活完了一生，你记不清具体说过什么，但记得几个时刻 | 通关后 24h 回忆测试：能复述 ≥3 个具体场景 |
| **结局后** | 先被信息击穿，再被"她当面说话"击穿，最后知道她们后来的人生 | 情绪自评三段递增，告别后 ≥7/10【标定】 |
| **第二周目**（D-09 新增） | 你带着自己的记忆重来，系统不提示，你只能靠"她这次的反应不一样"自己找因果 | 二周目玩家能自主说出 ≥1 条"我上次大概错在哪"的归因，且该归因与判定链一致 |

### 1.5 设计哲学（V2.1 修订，8 条）

**① 不做攻略游戏。** 不显示好感度、不提示最优解、不给攻略抓手；前台只给动态状态描述（§2.1）。

**② 人生不能重来——但不可逆的前提是公平。** 任何重大后果，必须在发生**之前**放出足量、可感知的信号，且信号写进事件卡、可被审计器扫描（§2.5）。玩家的失败必须是"我见过但我忽略了"，不能是"我不知道"。

**③ 选择有代价，不选也是选择。** 拖延、沉默、回避都有结算；没有无限期搁置的选择。

**④ 角色是独立人格。** NPC 有自己的生活、知识边界、误判权限。她可以判断错（§2.11）；但"她误判"与"系统没听懂"必须可区分（§2.12）。

**⑤ 教育意义 = 代价呈现，不是道德审判。** 系统永远不评价玩家，只展示后果。玩家的难受应由"她那一侧"产生，不由系统台词产生。

**⑥ 自由输入，但世界有锚点。** 系统不给选项，只给"说"的入口；场景必须有压力、有等待、有追问。

**⑦ 不设兜底的准确定义（D-04）。**
- **禁止**：选项框、意图重述菜单、"我没听懂，你是说……？"式系统纠错、"请重新输入"。
- **允许**：角色以自身性格追问、逼问、打断、冷场、离场——这是**演出**，不是**纠错**。
- 分界线：**屏幕上是否出现过系统的元语言（meta language）**。出现一次即违反 D-04。

**⑧ 一周目是镜子，二周目是练习场（D-09）。**
- 一周目：不可逆、无提示、无重来——把玩家打碎（P-OPEN-04 定的主次）。
- 通关后：解锁时间线回廊与重生；重生只是"再活一次"，系统不提示、不解释、不标答案。
- 这里同样有一条公平约束：**后果可感知，原因不可见**（§2.15）。不给原因，但必须给可比较的差异，否则学习退化成抽卡。

### 1.6 目标用户与不服务谁

**服务**：喜欢互动叙事/人生模拟，愿意被故事伤害，接受"没有最优解"，能接受 20 小时单周目且不介意慢热的人。

**明确不服务**（以此拒绝需求膨胀）：
- 想要"全 CG / 全结局收集"的收集型玩家 → 本作刻意让一周目不可全见。
- 想要"高自由度沙盒恋爱"的玩家 → 世界库是预定义事实，不是无限生成。
- 想要即时爽感的玩家 → 前 30 分钟没有奖励反馈。
- 想在本作里学"话术/套路"的玩家 → 本作只呈现代价，不提供最优表达（见 §9.6 伦理验收）。

### 1.7 成功标准

**M1 阶段（内部纵向切片，§8.3）门槛【标定】**：

| 指标 | 目标 | 测量方法 |
|---|---|---|
| 切片完成率 | ≥ 65% | ≥8 名被试，单情境包切片 |
| 意图识别低置信率 | ≤ 12% | `confidence < 0.55` 的轮次占比（§2.12） |
| 角色误解率 | 30%~70% | 判定为"她理解≠玩家本意"的轮次占比（§2.12） |
| 玩家主动说出"她在听我说话" | ≥ 70% | 结构访谈 |
| 结局片段情绪自评 | 告别后 ≥ 7/10 | 单题量表 |
| 单周目增量云成本 | ≤ $12（切片折算全量） | §7.1 模型实测替换 |

**上线指标（对外承诺，不许事后下调）【标定】**：
- 20 小时主线完成率 ≥ 25%（叙事游戏品类高线，取自同类公开值区间）。
- 结局到达者中愿意进入 NG+ 的比例 ≥ 40%。
- Steam 好评率 ≥ 80%，且 1 星差评中"被系统说教/羞辱"类占比 < 10%。

> **诚实标注**：以上均为**目标值**，不是已验证结果。M1 结束前，任何对外材料不得写成既定事实。

## §2 核心系统规格

### 2.1 六维情感（唯一命名）

**命名纪律**：本节为唯一合法命名。V1.1 的"放心程度"、AIgame 分支的"爱意/契合度/未来期待/委屈积攒值"**不得**出现在任何后续文档、代码字段或对外材料中；旧分支迁移时按本表映射（爱意→亲近、安全感→安心、契合度→认可、未来期待→依赖、委屈积攒→§2.2 积怨）。

| 代号 | 名称 | 定义 | 前台描述示例 | 初始值域【标定】 |
|---|---|---|---|---|
| AFF | 靠近意愿 | 她想不想主动靠近你 | 她最近愿意主动找你，但不确定你对她是不是特别 | 40~75 |
| TRU | 信任程度 | 她信不信你 | 她好像不太敢把心事交给你 | 35~70 |
| SEC | 安心程度 | 她和你在一起是否安心 | 你们之间好像隔了点什么 | 30~65 |
| RES | 认可程度 | 她是否认可你的人格与选择 | 她好像不太确定你是什么样的人 | 45~65 |
| DEP | 依赖程度 | 她情感上是否离不开你 | 她最近好像很需要你，但不敢说 | 30~65 |
| INT | 亲近程度 | 她想不想有更深的情绪与身体亲近 | 她靠近你的时候，又退回去了 | 25~70 |

**取值范围【锁】**：0~100 整数；NPC 可见性为"仅当前值"，无历史、无升降、无对比。

**变化规则（NC-3：只由规则引擎算）**：

```
Δdim = round( B(base) × M_intent × M_rel × M_char × M_decay )
```

| 因子 | 说明 | 取值 |
|---|---|---|
| `B(base)` | 事件卡或对话意图给出的基础增量 | 日常 −1~+2；关键 −15~+15【标定】 |
| `M_intent` | 意图匹配修正 | 匹配她的"最看重"维度 ×1.3；触碰底线 ×0（并触发 §2.8） |
| `M_rel` | 当前关系状态修正 | 确立关系后 AFF/INT 增益 ×0.6；分手后 ×0.2 |
| `M_char` | 性格修正 | 见各角色卡权重；苏遥对 RES 敏感 ×1.5【标定】 |
| `M_decay` | 边际递减 | 同一维度 24 游戏小时内第 2 次起 ×0.8、第 3 次起 ×0.6、第 4 次起 ×0.3 |

**前台描述生成（LLM 唯一合法用途之一）**：输入 = 分数段（5 档，不传精确值）+ 性格 + 最近 3 条事件 + 当前场景；输出 = 1 句中文描述。约束：禁止出现数字、禁止比较、禁止升降、同一状态 24 游戏小时内不得重复措辞。

### 2.2 隐藏张力五维

**不显示，只影响行为**。0~100【锁】。

| 代号 | 名称 | 定义 | 主要作用 | 变化方向 |
|---|---|---|---|---|
| JEA | 嫉妒/占有 | 对别人靠近你的敏感度 | 放大 CROSS 类事件触发率；提高暴露概率 | 看到你与多人互动 +1~+4【标定】 |
| TOL | 容忍/原谅 | 对错误、隐瞒、劈腿的包容度 | 进入 §2.7 分母；一次误解后的恢复上限 | 被真诚修复 +1~+3；被重复伤害 −3~−8 |
| DEB | 亏欠 | 你付出后她产生的愧疚与补偿 | 短期内提高 AFF/DEP，长期转化为积怨 | 单方面付出累积 +1~+3 |
| FAT | 倦怠 | 长期关系中的新鲜感流失 | 降低 AFF/INT 增益；提高离开意愿 | 每章自然 +2~+5；新鲜事件 −5~−10 |
| **GRV** | **积怨（新增，P-OPEN-03）** | 未被清算的伤害记账 | "延迟清算型"的触发源；不清零，只在清算时释放 | 每次未被解释的伤害 +2~+6；从不自然衰减 |

**GRV 规则【锁】**：`GRV` 一旦超过角色阈值（林晚 55、苏遥 45、顾焰 60、沈宁 50【标定】），该角色进入"清算预备"状态；受 D-05 约束，清算必须由具体事件触发，不得随机爆发。

### 2.3 暗恋轴

**完全不显示，只在结局揭晓**。0~100【锁】。

| 代号 | 名称 | 定义 |
|---|---|---|
| CNS | 关注度 | 她是否总在注意你 |
| EXP | 期待值 | 她是否幻想过和你在一起 |
| SUP | 表达抑制 | 为什么不说：自卑 / 怕破坏关系 / 道德约束 |
| APV | 克制·回避 | 越心动越躲（正值）还是越心动越靠近（负值） |

**暗恋判定公式【标定】**：`CRUSH = 0.35·CNS + 0.30·EXP + 0.35·SUP − 0.20·|APV|`，且必须同时满足 `CRUSH ≥ 60` 与 §2.4 的行为门限。

**规则【锁】**：
- 暗恋者从不主动建立恋爱关系，只能暗示、试探、等待。
- 玩家与其他人确立关系后，暗恋线转入隐藏态，不再推进，但不清零。
- 过程中只允许极少数可察觉细节（§2.5 线索配额），**绝不点破**。

### 2.4 暗恋者产生与生命周期（P-OPEN-01）

**产生（四步，全程无随机发牌）**：

1. **性格前置**：角色卡暗恋潜质 ≥ 阈值（林晚 85、苏遥 75、顾焰 50、沈宁 35【标定】）。
2. **行为门限**：玩家对该角色的"无意识特殊对待"累积值 ≥ 门限（如反复深夜回复、记住小事、避开别人找她）。累积值只由事件与对话意图计算，不由随机数产生。
3. **候选确认**：若同时有 ≥2 人过门限，取累积值高者；同分才允许在候选间做 `<5%` 扰动【标定】。
4. **锁定**：开局锁定（`truth.crush`），整局只读；玩家侧不可见。

**生命周期**：`萌芽 → 加深 → 抑制 → （退场 | 揭示）`。每个阶段的 CNS/EXP/SUP 变化规则写进事件卡 `crush_axis` 字段（§2.9）。

**退场条件**：玩家确立关系、角色离开城市、角色结婚。**揭示条件**：仅结局（§2.14）。

> **与原实现的分歧记录**：AIgame 分支的 `truth.js` 写的是"暗恋由 seed 决定"。该实现**不符合本版 P-OPEN-01**。若 V0 复用该代码，必须先把 `crushes` 的生成改成门限模型，否则结局归因会退化为抽奖（R-11）。

### 2.5 公平性契约（FC）

**FC 是本产品的伦理地基。** 没有它，"不可逆"就是欺负玩家。

| 编号 | 条款 | 可验收判据 |
|---|---|---|
| **FC-1** | 每个进入结局池的暴击，必须有 ≥3 条可感知线索 | 审计器扫描事件卡 `visible_clues[]`，少于 3 条直接报错 |
| **FC-2** | ≥1 条线索必须落在**必经事件**中 | 线索的 `mandatory: true` 且所属事件 `delivery: guaranteed` |
| **FC-3** | 线索必须是"当时语境下不重要"的信息 | 线索所在事件的 `emotional_salience ≤ 2`（1~5 档），否则视为刻意提示 |
| **FC-4** | 任何不可逆后果必须有"视而不见窗口" | 后果前至少 1 个可交互场景，玩家可主动追问/离开；窗口内不作为 = 接受后果 |
| **FC-5** | 线索可见性分三级，每条必须标注 | `显性`（当场可懂）/`半显性`（当场可疑）/`隐微`（回看才懂）。单个暴击至少含 1 条半显性 |

**误解预算（新硬指标）【标定】**：单局内"角色理解 ≠ 玩家本意"的轮次占比必须落在 **30%~70%**。
- `<30%`：角色像机器，玩家感觉不到"她有自己的滤镜"，产品最贵的部分消失，判为不达标。
- `>70%`：玩家挫败上升，且判定链大概率有 bug，判为不达标。
- 该指标同时是 §2.12 审计器的输出项与 §1.7 M1 门禁项。

### 2.6 关系状态机

单角色状态：`陌生 → 认识 → 亲近 → 暧昧 → 确立 → (危机) → (分手 | 相伴)`；另有旁支 `未开始·窗口关闭`、`暗恋·隐藏`。

| 迁移 | 条件【标定】 | 不可逆性 |
|---|---|---|
| 陌生→认识 | 首次事件卡触发 | 可逆（长期无互动退回陌生） |
| 认识→亲近 | AFF ≥ 50 且 TRU ≥ 45 | 可逆（信任跌破 30 退回） |
| 亲近→暧昧 | AFF ≥ 65 且 INT ≥ 55 且至少 1 次专属事件 | 可逆 |
| 暧昧→确立 | 双方意图 `I10 示好/表白` 且在窗口内；或被第三方抢先 | **不可逆**（本周目） |
| 确立→危机 | TRU 受损 ≥ 20 或 触发 §2.8 | 可逆（修复有上限） |
| 危机→分手 | §2.7 判定通过 | **不可逆** |
| 危机→相伴 | §2.7 判定未通过且修复事件达成 | 可逆 |
| 任意→未开始·窗口关闭 | 该角色关键窗口事件全部错过 | **不可逆** |

### 2.7 分手判定与定局判定

**分手（NC-3：纯规则）**【标定】：

```
继续意愿 CR = 0.30·AFF + 0.20·DEP + 0.15·RES + 0.15·TOL + 0.10·DEB + 0.10·MEM − 0.10·FAT
离开意愿 LV = 0.25·(100−TRU) + 0.20·(100−RES) + 0.20·(100−SEC) + 0.15·JEA + 0.10·FAT + 0.10·GRV
```

- `MEM`（共同回忆）= `min(100, 3 × 已结算的共同事件数 + 2 × 结局权重和)`，只增不减。
- 判定：`LV − CR ≥ θ(char)` **且** 触发清算事件 → 进入分手；`θ`：林晚 8、苏遥 0、顾焰 5、沈宁 10。
- **一票否决**（无视分数，直接进入分手结算）：劈腿被抓到证据等级 ≥2；连续 1 章零互动（冷暴力）；触碰该角色底线事件。
- **分手类型**：NPC 主动 / 玩家被分手 / 双方同时 / 劈腿被发现 / 长期冷落退场。类型由"最后触发的意图"决定，写进结局族输入。
- **修复约束**：带伤修复后 `TOL` 上限锁定为原值 ×0.7，`GRV` 不清零（"裂痕永远在"）。

**定局判定**：所有女主状态 ∈ `{相伴, 分手, 未开始·窗口关闭}` 且无进行中的暗恋推进 → 定局。定局后时间加速（§2.13），进入 §2.14。

### 2.8 隐瞒与暴露（D-05）

**硬约束【锁】**：玩家侧的背德行为**必然被发现**；但**时机与方式必须对玩家不可预测**。

| 暴露路径 | 触发条件 | 单调性 |
|---|---|---|
| 社交圈重叠 | 共同朋友数量 ≥2 且 JEA ≥ 40 | 提高 |
| 数字痕迹 | 玩家留下 ≥2 条可关联痕迹（聊天/消费/照片） | 提高 |
| 行为矛盾 | 玩家前后说辞 `I03 解释` 与事实冲突 ≥1 次 | 提高 |
| 第三方介入 | 该角色已有 ≥1 个"知情 NPC" | 提高 |
| 意外撞见 | 场景交叉点重叠 | 随机，但概率随 JEA 上升 |
| 自己说漏嘴 | 同一场对话内出现 ≥2 处事实冲突 | 提高 |

**三档时机【标定】**：`当周 / 下一关键节点 / 结局前`——由 `EXPOSE_TIMING` 决定，且必须保证 **发现前存在 ≥1 次"视而不见窗口"**（FC-4）。

**禁止**：在玩家完全没有行为痕迹时触发暴露（那是冤案）；也禁止玩家痕迹极多时永远不触发（那是欺骗）。

### 2.9 事件卡 Schema（双面）

每张事件卡 = 一个 JSON 对象。字段分组如下（`*` = 必填）。

| 字段 | 类型 | 说明 |
|---|---|---|
| `id`* | string | 形如 `LIN-006`，前缀见 §8.1 |
| `type`* | enum | daily / key / conflict / crush / return / crisis / gen / cross / cond / end |
| `stage`* | enum | 少年 / 青年 / 大学 / 初入社会 / 成年 / 婚姻 / 中年 / 收束 |
| `title`* | string | 事件名 |
| `trigger`* | object | `{stage, relState, dimThreshold, preEvents[], weight}` |
| `cast`* | string[] | 谁在场、谁知情、谁受影响（知情者必须进 §3.3 知识表） |
| `mutex` | string[] | 互斥事件 |
| `scene`* | object | 地点、氛围、镜头预设 |
| `dialogue_skeleton`* | object | 必须推进的信息、可选走向、情绪基调 |
| `effects`* | object | 六维/张力/暗恋/玩家侧的增量，逐角色逐维 |
| `npc_side`* | object | **NPC 侧**：同一时间她在哪、做什么、看到什么、想什么、做了什么（NC-2） |
| `cross_point` | object | 双线交叉点：`{t, relation: same\|miss\|offset}` |
| `visible_clues[]` | array | 玩家侧可见线索，每条 `{text, level: 显性\|半显性\|隐微, mandatory, salience}` |
| `hidden_clues[]` | array | 只在结局揭示的细节 |
| `ending_pool` | object | `{enter: bool, weight, beat}` |
| `composable_tags[]` | string[] | 可拼接/前置/互斥标签 |
| `llm_freedom`* | object | 哪些必须固定、哪些可即兴（默认：数值与走向固定，措辞自由） |
| `quota` | object | 投递配额与冷却（§2.10） |

**校验规则**：`npc_side` 必填且必须能在 §3 世界库中找到 `causeId`，否则该卡不得入库（NC-2）。

### 2.10 导演组装器与最低接触保证

**组装流程**：`筛选候选池 → 计算权重 → 冷却过滤 → 配额优先 → 抽取 → 记录 cross_point`。

**权重公式**【标定】：

```
W = W_base × M_char × M_state × M_rhythm × M_random
M_random ∈ [0.95, 1.05]        # 只扰动权重，不改判定
M_rhythm = 1 + 0.3 × min(3, 距上次同类事件的章数)   # 避免事件扎堆或长期空窗
```

**三条硬规则**：
1. **最低接触保证（P-OPEN-02）**：每位女主**每章 ≥3 个必投递事件**（`delivery: guaranteed`），不论玩家状态如何。违反视为内容作废。
2. **冷却**：同一事件卡全局只触发一次；同一角色两事件间至少间隔 1 个游戏内事件。
3. **冲突升级约束**：`crisis` 类事件强度 ≤ 上一次同类事件强度 +1 档，禁止无铺垫跳级（防止"突然爆发"破坏 FC）。

**导演不得做的事**：不创作事件、不现场编 NPC 侧素材、不改数值、不替 LLM 生成台词。它只做**选择、组合、排列**。

### 2.11 对话介入层与意图契约（D-04）

**形态**：远程/异步（侧边 1/5 半透明消息流，2~3 条，几秒淡出，无历史）+ 面对面（底部极细输入条"按住说话/输入"）。无 UI 数值、无已读回执、无回看。

**意图原语（封闭 16 个，工程侧使用，永不向玩家展示）**：

| 编号 | 原语 | 编号 | 原语 |
|---|---|---|---|
| I01 | 承认事实 | I09 | 拒绝 |
| I02 | 否认（撒谎） | I10 | 示好/表白 |
| I03 | 解释 | I11 | 试探 |
| I04 | 道歉 | I12 | 指责/攻击 |
| I05 | 沉默 | I13 | 求助 |
| I06 | 回避/转移 | I14 | 安慰 |
| I07 | 追问/反问 | I15 | 命令/要求 |
| I08 | 承诺 | I16 | 玩笑/调侃 |
| I13 | 求助 | I14 | 安慰 |

**唯一允许的终止态**：`T1 离场/挂断`（由角色主动触发，不由系统触发）。

**易混矩阵（分类器必查，判定链必记）**：解释↔撒谎、道歉↔承认、沉默↔回避、试探↔追问、示好↔玩笑、指责↔追问。

**低置信处理（严禁走纠错）**：
- `confidence < 0.55` → 走**角色追问**路径：由该角色按性格定制的问题库发问（如顾焰："你别绕，我就问你去哪了。"；沈宁："你是想说分手吗？"）。
- 单场追问上限 1 次；同一场超过 1 次视为本场"表达不清"，剧情按"她没听懂"推进——**这正是设计意图**，不是失败。
- **禁止项清单（违反即视为 bug）**：选项框、意图列表、"你是说…？"以外任何系统元语言、要求重新输入、显示识别置信度。

### 2.12 判定链与审计（新增，缺口补齐）

**问题（为什么必须有）**：玩家无法区分"她按人设误解我"与"系统没听懂我"。没有判定链，"允许 AI 识别错"就是所有 bug 的遮羞布。

**每回合必须落一条 `round_record`**：

| 字段 | 说明 |
|---|---|
| `roundId` / `gameTime` / `sessionSeed` / `npcId` | 定位 |
| `rawText` / `asrConf` / `audioEmotion`（模糊标签，§6.4） | 输入原始证据 |
| `intents[]` | top3 `{id, confidence}` |
| `judge` | 四层判定：`content` / `intent` / `emotion` / `relation`（V1.1 第 9.1 节的四件事） |
| `npcDirective` | 给表达层的指令（不含台词） |
| `stateDelta` | 实际写入的数值变化（必须由规则引擎产生） |
| `causeId` | 若产生 NPC 侧记录，必须回指世界库因果 |
| `lowConfFlag` / `metaLangFlag` | 低置信标记 / 系统元语言出现标记（恒为 false） |

**审计器断言（§9.1）**：
1. `metaLangFlag` 必须恒为 false，出现一次即违规；
2. 低置信轮次必须走追问路径，不得走纠错；
3. 角色误解率必须落在 §2.5 的 30%~70%；
4. 每条 `stateDelta` 必须能回指一条 `causeId` 或一条意图（防 LLM 写数值）。

### 2.13 时间推进与章节配额

**七章【锁】**：少年 / 青年 / 大学 / 初入社会 / 成年 / 婚姻 / 中年 + 收束段。时间自动流逝，同章内不设固定日/周循环。

| 章 | 主线时长【标定】 | 通讯权重 | 场景权重 | 关键节点 |
|---|---|---|---|---|
| 少年 | 1.5h | 低 | 高 | 分班、转学、毕业合影 |
| 青年 | 2h | 中 | 高 | 异地、初恋、第一次劈腿可能 |
| 大学 | 2h | 高 | 中 | 白月光退场、热烈恋人登场 |
| 初入社会 | 2.5h | 高 | 中 | 职场、相亲、现实压力 |
| 成年 | 2.5h | 中 | 高 | 结婚、买房、生育分歧 |
| 婚姻 | 2h | 中 | 高 | 婚后平淡、出轨、离婚 |
| 中年 | 1.5~2h | 低 | 高 | 旧人返场、父母生病/葬礼、定局 |
| 收束 | 5~15min | — | — | 时间加速 → §2.14 |

**后期加速【锁】**：婚后与定局后不再逐日推进，只保留关键节点；加速段不产生新事件，只回收已有记录。

### 2.14 结局族、三层视频与 AI 告别

**结局族【锁】**：相伴到老 / 孤独终老 / 出轨毁灭 / 暗恋错过 / 被伤透后独行 / 中年重逢已无爱 / 带伤修复。判定输入 = 各角色终态 + 分手类型 + 暗恋揭示数 + 玩家侧状态（§4）。

**结局顺序【锁】（D-06）**：`定局判定 → 结局视频 → 黑屏数秒 → AI 告别 → 时间线回廊 → 完全重置 / NG+ 解锁`。

**结局视频三层结构**：

| 层 | 内容 | 素材来源 |
|---|---|---|
| 玩家视角 | 他做过的选择、说过的话、错过的瞬间 | 玩家侧事件日志 |
| NPC 视角 | 同一时刻她看到/感到/做了什么他不知道的事 | 世界库 NPC 侧记录（§3.7） |
| 上帝视角 | 两条线并置，展示"你们隔了什么" | 交叉点对齐（§3.6） |

**组装语法**：`beat = (t, playerClip | npcClip, crossRelation, narration)`；同一 `t` 最多 1 个玩家 clip + 1 个 NPC clip；缺失一侧时用"空镜 + 旁白"补，**禁止现编画面**（NC-2）。

**AI 告别排序公式【标定】**：

```
PAIN(i) = 0.35·伤害深度 + 0.25·关系终态深度 + 0.20·暗恋权重 + 0.20·等待时长
```

最后压轴 = `argmax PAIN`（"谁被伤得最深、等得最久、最后都没说出口"由玩家本局行为算出，不由系统指定）。玩家可以回应，但改变不了结局；回应记录进入时间线回廊。

### 2.15 重生 NG+ 与确定性重放（D-09，新原语落地）

**解锁**：仅在通关后（D-06）。一周目内绝不出现任何"重来"入口（NC-1）。

**可选起点**：每章章首检查点（7 个）。玩家选一个时间点重新活，**系统不提示、不解释、不标答案**。

**保留 / 不保留**：

| 保留 | 不保留（且不显示） |
|---|---|
| 玩家自己的记忆（人脑，不是系统给的） | 上次的判定链、原因、数值变化 |
| 已解锁图鉴/时间线回廊（只读） | 任何"你上次做错了什么"类提示 |
| 设置与偏好 | 任何"推荐选项" |

**重放机制（工程硬要求）**：

```
快照 snapshot = {chapterId, t, worldState, playerState, npcStates[], knowledgeTable, eventLogLength, seed, sha256}
重放 replay = simulate(snapshot, 新输入日志)   # 确定性
断言：同一输入日志 → 重放后的 stateHash 必须等于原 hash
```

- 状态必须由规则引擎计算（NC-3），LLM 不参与状态，因此重放可复现。
- 表达层允许文本不同（同一状态下不同措辞是特性，不是 bug），但**判定必须一致**。
- 快照与输入日志必须在 M1 就建起来（基础设施级），后补成本极高（R-12）。

**"后果可感知、原因不可见"（§1.5 ⑧ 的执行口径）**：
- 必须给：她走了/她哭了/日期与场景、同一节点她说了不一样的话、玩家可自己对比的差异。
- 禁止给：系统解释、原因提示、对错判定、复盘报告。
- 学习闭环的验收：二周目玩家能自主说出 ≥1 条"我上次大概错在哪"，且与判定链一致（§1.4 表第 5 行）。

## §3 世界库规格

### 3.1 定位与五条不变量

世界库 = **客观事实层 + 多主体状态机 + 知识边界 + 因果链**。它是 NPC 侧素材的唯一合法来源（NC-2），也是 §1.3 中 `trace` 原语的实现。

| 编号 | 不变量 | 违反即事故 |
|---|---|---|
| **W-1** | 世界库独立于 LLM：LLM **只读，不可写** | LLM 编出一条"她其实一直在等你" |
| **W-2** | 一切 NPC 侧记录必须有 `causeId` | 结局素材凭空出现 |
| **W-3** | 知识边界严格：不知道就是不知道，不许全知 | NPC 说出她不可能知道的事 |
| **W-4** | 时间单向递增（一周目内） | 出现回退/重放导致的时间倒流 |
| **W-5** | 同一客观时刻，玩家侧与 NPC 侧必须可对齐 | 结局双线并置错位 |

### 3.2 主体（Subject）

| 字段 | 类型 | 说明 |
|---|---|---|
| `id`* | string | `npc:linwan` / `player` / `org:laojie` |
| `kind`* | enum | npc / player / org |
| `name`* | string | — |
| `life`* | object | `{born, stage, alive}` |
| `attrs`* | object | 职业、健康、金钱、情绪、所在地；每项带 `t_from` |
| `schedule` | object | 日程模板（周/季节），驱动 tick（§3.6） |
| `relations[]` | array | `{target, type: 亲属/朋友/同事/暗恋/恋人, strength}` |
| `personality_ref`* | string | 指向 §2 角色卡与权重 |
| `knowledge_ref`* | string | 指向 §3.4 知识表 |

### 3.3 事实（Fact）与证据等级

| 字段 | 说明 |
|---|---|
| `factId`* | `F-000123` |
| `predicate`* | 谓语（住院 / 拆迁 / 加班 / 结婚） |
| `subject[]`* / `object` | 谁 / 对谁或什么 |
| `t_from`* / `t_to` | 生效区间 |
| `value` | 具体值（可空） |
| `grade`* | `S` 创作设定（长河唯一合法）；`A` 一手（正史/档案/当事人）；`B` 二手（笔记/回忆/转述）；`C` 推断（必须标注）；**史鉴才允许 A/B/C** |
| `ref` | 出处（史鉴必填：书名/卷/页；长河填设定稿编号） |
| `confidence`* | 0~1；`<0.6` 的事实不得成为不可逆判定的唯一依据 |

**规则**：长河内不得出现 `grade ≠ S` 的事实（防止把现实史实当设定混入）；史鉴内不得出现 `grade = S` 的事实（防止创作冒充史料）。这是 §1.3"两种验收不可混用"的数据层落地。

### 3.4 知识边界表（K-table）

| 字段 | 说明 |
|---|---|
| `subjectId`* | 谁知道 |
| `factId`* | 知道什么 |
| `know`* | `known` / `suspect`（怀疑）/ `unknown` |
| `learn_t`* | 何时知道（`unknown` 时为空） |
| `channel`* | 通过什么渠道知道（看见/被告知/传话/推断/撞见） |
| `certainty`* | 0~1，影响 §2.12 四层判定 |

**硬规则**：
1. NPC 只能引用 `know = known` 的事实；`suspect` 只能说"我怀疑/我听说"，不得陈述为事实。
2. NPC 不得引用其他主体的 K 表（禁止上帝视角）。
3. 玩家行为导致的知情必须写 `channel`，否则不得作为暴露依据（§2.8）。

### 3.5 因果链与校验

| 字段 | 说明 |
|---|---|
| `causeId`* | `C-000045` |
| `effectRef`* | 指向事件卡 / NPC 侧记录 / 状态变化 |
| `preconditions[]`* | 前置事实与前置状态 |
| `requiredKnowledge[]` | 触发者必须知道的事实 |
| `t`* | 因果发生时刻（必须 ≤ 效果时刻） |

**校验器（§9.3）**：① 无 `causeId` 的 NPC 侧记录不得入结局池；② 循环引用检测；③ 时间单调；④ `requiredKnowledge` 必须在该主体的 K 表中为 `known`。

### 3.6 tick 推进与交叉点

**tick 粒度**：1 游戏日；阶段内按日推进，阶段外按节点跳转。

```
每日 tick: for each subject: 应用 schedule → 结算到期事件 → 更新情绪 → 从公共事实更新知识 → 采样（§3.7）
```

**交叉点对齐**（结局双线并置的依据）：

| relation | 含义 | 判定 |
|---|---|---|
| `same` | 同一时刻两人在同一空间 | 地点相同且时间差 ≤ 1 日 |
| `miss` | 同一时刻两人在不同空间，且本可相遇 | 地点相邻/同城且事件相关 |
| `offset` | 一前一后，因果相关 | 时间差 ≤ 7 日且存在因果边 |

### 3.7 NPC 侧关键性采样（替代"每次互动都记一条"）

V1.1 的"每次互动后生成一条 NPC 侧微事件"成本不可行（20h × 每回合）且大部分无回收价值。本版改为**关键性采样**：

**采样条件（满足任一即采样）**：① 与玩家有直接交互；② 任一关系维度变化 ≥3；③ 暗恋轴任一维变化 ≥5；④ 该记录的 `ending_pool.weight ≥ 40`；⑤ 玩家错过了一个关键窗口事件。

**配额**：每章 ≤40 条【标定】；超出按 `ending_pool.weight` 降采样；低于 10 条视为该章 NPC 侧记录不足，判内容不达标。

**记录 schema**：`{recordId, t, npcId, causeId, where, doing, saw, thought, did, endingPoolWeight, crossPoint}`。

### 3.8 与 LLM 的读写边界与性能

**只读 API（LLM 侧唯一入口）**：`queryFacts(subject, tRange)`、`queryKnowledge(subject, factId)`、`queryTimeline(subject, tRange)`、`queryCrossPoints(tRange)`。**无任何写接口**（W-1）。

**性能约束【标定】**：单次查询 ≤5ms；世界库常驻内存，20h 全量事实/知识条目 ≤ 5 万条；每日 tick ≤2ms。

## §4 玩家侧建模

### 4.1 玩家四维

V1.1/V2.0 缺玩家侧建模，导致"责任与代价"只作用于 NPC，玩家自己不承担后果。补四维（0~100【锁】）：

| 代号 | 维度 | 说明 | 不显示 |
|---|---|---|---|
| CAR | 事业 | 工作进展、职业风险 | 只通过事件与场景体现 |
| HEA | 健康 | 熬夜、饮酒、长期压力 | 通过她的反应与身体信号体现 |
| MON | 金钱 | 收入、负债、买房压力 | 通过选择受限体现 |
| PSY | 心理 | 自我认知、能否爱人、能否爱自己 | 通过内心独白与结局族体现 |

### 4.2 反向作用（玩家状态必须真实影响世界）

1. **事件可选性**：`CAR < 40` 时事业线事件降权，婚姻/家庭线升权。
2. **NPC 反应**：`PSY < 35` 时，玩家表达被判定为"不稳定"，NPC 的 `SEC/TRU` 增益 ×0.7。
3. **结局族**：`PSY` 是"孤独终老 / 被伤透后独行"的必要条件之一（非充分，仍须 §2.7 判定）。
4. **只能单向**：NPC 不得直接改玩家四维以外的隐藏值；玩家四维变化必须回指玩家侧事件或玩家意图（审计项，§9.1）。

### 4.3 验收

玩家四维在任何 UI 上都**不可见**（NC-1 推论）。验收标准：M1 试玩中，被试应能自主说出 ≥1 条"我因为熬夜/只顾工作，她开始不高兴了"，且该因果在事件日志中存在。

## §5 若要做：内容生产管线与产能

### 5.1 七步流水线

| 步 | 产出 | 责任岗 | 闸门 |

## §6 技术架构

### 6.1 分层

| 层 | 组件 | 是否允许 LLM 参与 |
|---|---|---|
| 客户端 | 瘦客户端（云）/ PC 本地渲染、输入（打字/按住说话）、演出播放 | 否 |
| 接入层 | 会话管理、流式网关、限流与降级策略（事先声明，非静默） | 否 |
| **规则层（确定性）** | 世界库、六维/张力/暗恋、导演组装器、判定链、结局判定 | **否（NC-3）** |
| 编排层 | 回合编排、记忆压缩、上下文组装、工具调用（只读世界库） | 是（但不得写状态） |
| 表达层 | LLM 台词、TTS、口型/表情驱动、旁白润色 | **是（唯一自由区）** |
| 资产层 | 微动作库、场景库、音频库、预渲过场 | 否 |

### 6.2 对话回合管线与延迟预算

```
输入 → ASR(流式) → 意图分类 → 规则判定(确定性) → 上下文组装 → LLM 首句 → TTS 流式 → 驱动 → 播出
```

| 环节 | 预算【标定】 | 说明 |
|---|---|---|
| ASR 流式 | 250ms | 边说边识别；松手后 250ms 出终稿 |
| 意图分类 | 120ms | 本地小模型，输出 top3 |
| 规则判定 | 20ms | 确定性引擎 |
| LLM 首 token | 600ms | **只生成首句**，不生成整段 |
| TTS 首包 | 300ms | 流式，出前几个词即可开播 |
| 口型/表情 | 100ms | 音频驱动，不等完整文本 |
| **合计** | **≈1.4s** | 目标 1.5~2s；关键剧情可放宽到 3s（可预渲） |

**填时间手段（必须实现，不是可选）**：正在输入、呼吸、动作过渡、语气词、眼神偏移、环境声。原则：**先用非语言填，再播语言**。

### 6.3 渲染与平台（D-03）

| 场景 | 渲染方式 | 理由 |
|---|---|---|
| 对话/日常 | 实时 MetaHuman，低码率，表情+微动作 | 需要即时反应 |
| 关键过场 | 预制片段或预渲视频流（40~60min 总量，§8.1） | 保画质、控成本 |
| 结局视频 | 云端渲染（预渲 + 组装） | 5~10min 完整版，可异步 |
| PC | 本地渲染对话场景 | 省云成本 |
| 移动 | 全云 | 设备能力不一 |

### 6.4 语音链路与情感识别边界（D-11）

**分层**：

| 阶段 | 形态 | 理由 |
|---|---|---|
| M1（V0/V1 切片） | **异步语音**：按住说话 → 转写 → 显示你自己说的话 → 她回应 | 延迟要求低，体验保留"我说了" |
| V1 后期 | 面对面实时语音 | 1.5s 在语音里是灾难，必须有 §6.2 全套填时间 |
| 全量 | 语音为主、打字同等重要 | 公共场合语音尴尬（V1.1 第 11.4 节） |

**情感识别边界【锁】**：
- 输出只能是**模糊标签**（如 `情绪倾向：偏低/中性/偏高`，`语速：慢/中/快`），不得输出"愤怒/心虚"等硬判定。
- 只进入 **表达层**（决定"她怎么回应"），**不得进入判定层**（不决定数值与走向）。
- 理由：识别错时，它自然成为"她的误判"（符合设计哲学）；一旦进判定层，一次错误就击穿"她在听我说话"的幻觉（R-02）。
- 隐私：录音默认不落盘，仅保留特征；授权与删除入口必须显式（§6.6）。

### 6.5 存档、快照与确定性重放

**存档三件套**：`snapshot`（§2.15 定义）+ `inputLog`（玩家输入序列）+ `seed`。

| 要求 | 规格 |
|---|---|
| 确定性 | 同一 `snapshot + inputLog + seed` → 状态 hash 必须一致；CI 里跑重放断言 |
| 快照时机 | 每章章首 + 每次进入关键节点前 |
| 版本兼容 | 引擎版本写入快照；不兼容时**禁止读档**（防炸档），但要提示可重开 |
| 用途边界 | 只用于重生（D-09）与技术调试；**一周目不可用**（NC-1） |
| 存储 | 快照 ≤200KB/个；输入日志本地 + 云端加密 |

### 6.6 合规、分级与数据（D-07）

1. **双版本隔离**：海外/Steam 版按完整表达设计；国内版另做尺度适配，内容差异走内容开关，不共用同一份已过审素材。
2. **语音与隐私**：麦克风、录音、情感分析必须显式授权；提供"只用打字"等价路径；数据保留期 ≤18 个月，可一键删除。
3. **分级**：海外按 ESRB/PEGI 申报（含成人情感题材）；国内版按现行规范另报。
4. **肖像与声音**：MetaHuman/语音克隆必须取得演员书面授权，授权范围覆盖"生成式演绎"，期限与地域写进合同（§7.5）。
5. **未成年人**：默认不面向未成年人，年龄门槛与提示必须在商店页与首启页出现。

## §9 QA、遥测与审计

### 9.1 判定链审计器（`audit-round`）

| 断言 | 判据 | 失败处置 |
|---|---|---|
| A1 无系统元语言 | `metaLangFlag == false` 全域 | 直接判 bug，阻断合入 |
| A2 低置信必走追问 | `lowConf == true` 的轮次 `npcDirective == 追问` | 阻断 |
| A3 误解率在界 | 30% ≤ 误解率 ≤ 70%（§2.5） | 出报告，人工裁决 |
| A4 状态变化可回指 | 每条 `stateDelta` 有 `causeId` 或意图 | 阻断 |
| A5 无语义漂移 | 同一状态下的 `npcDirective` 与角色卡一致（抽查 5%/章） | 出报告 |

### 9.2 公平性审计器（`audit-fc`）

扫描全部进入 `ending_pool` 的事件卡：`visible_clues ≥3`（FC-1）、`mandatory` 线索 ≥1（FC-2）、`salience ≤2`（FC-3）、不可逆后果前有交互窗口（FC-4）、至少 1 条半显性（FC-5）。**任一不通过 → 该卡不得入库**。

### 9.3 世界库因果审计器（`audit-trace`）

① NPC 侧记录必须有 `causeId`（NC-2）；② 无循环引用；③ `cause.t ≤ effect.t`；④ `requiredKnowledge` 在 K 表中为 `known`（W-3）；⑤ 长河内不得出现 `grade ≠ S` 的事实（§3.3）。

### 9.4 遥测与埋点（脱敏后）

| 埋点 | 用途 |
|---|---|
| `round_record` 全量（脱敏） | 判定链复盘、误解率、低置信率 |
| `low_conf` / `misunderstanding` 计数 | M1 门禁 |
| `fc_violation` | 公平性回归 |
| `chapter_completion` / `rage_quit_point` | 留存曲线（R-07） |
| `emotional_selfreport`（三段） | 结局情绪验证 |
| `ng_plus_entry` | 二周目意愿（§1.7） |
| `replay_hash_mismatch` | 确定性回归（§6.5） |

**隐私**：默认不上传原始音频；文本脱敏后再上传；保留 ≤18 个月；可一键删除（§6.6）。

### 9.5 M1 验收门

逐项对照 §1.7 的 6 项 M1 指标 + §9.1~§9.3 三审计器全绿 + §6.5 重放断言通过。**全部通过才可进入 M2**；不通过按 §8.3 处理。

### 9.6 内容包伦理验收（D-12 配套）

每个内容包发布前必须逐条勾选：

| 编号 | 条款 |
|---|---|
| E1 | 至少 1 个"玩家自己难受"的时刻，且**没有系统评判台词** |
| E2 | 不把伤害行为包装成技巧/攻略；不出现"正确话术"提示或暗示 |
| E3 | 被伤害的一方必须有人格、有后果，不是工具人 |
| E4 | 结局不给"最优解"结论，只展示代价 |
| E5 | 敏感题材（出轨、长期单恋、背叛）需双人评审签字 |
| E6 | 通过 §9.2 公平性审计（暴击必须可回溯） |

### 9.7 史鉴回测实验（内部，D-08 + P-OPEN-05）

**目的**：验证 `trace` + `tick` 是否真的能产出"可证伪"的结果，而不是流畅的漂亮话。

**三步**：
1. 选一段结局明确、史料充足、主体数 ≤20 的历史情境；
2. 把结局从世界库移除（引擎不知道），只放 `grade A/B` 事实与 K 表；
3. 跑 tick 至终点，比对引擎结果与真实结局。

**判定**：`收敛`（关键结局一致）/ `部分收敛`（方向对、细节偏）/ `不收敛`。只有"收敛"才允许对外说内核具备可证伪能力（P-OPEN-05 未裁决前，一律不对外）。

**硬边界**：只用 A/B/C 证据等级，禁止 `S`；结论文档一律用"假设/推演"表述；不得宣称历史真相。
